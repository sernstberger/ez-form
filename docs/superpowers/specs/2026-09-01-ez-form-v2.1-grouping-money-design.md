# ez-form v2.1 — live digit grouping and `MoneyField`

Decided with Steve, Sept 1 2026.

## Goals

1. `NumberField` shows thousands separators **while typing** (`1000` → `1,000` before blur). The form value stays `number | null`.
2. `MoneyField`: a US-dollar field built on `NumberField`. Value is a `number` in dollars (`19.99`), never cents, never a string.

## Non-goals

- Live currency symbol or forced two decimals while typing. Base UI already renders `$1,234.50` on blur via `format`; that stays the blur behavior.
- Locales other than what the consumer passes to `locale`/`format`. `MoneyField` pins `en-US` + USD.
- Any new dependency. (react-number-format was considered and rejected: separate control, no steppers.)

## Facts this design rests on

- Base UI `NumberField` parses grouped text (`parse.js` strips the locale's group separator and currency symbol) and formats with grouping on blur, but deliberately does not rewrite the text during typing (`NumberFieldRoot.js`: "During direct typing we don't want to overwrite the user-provided text until blur").
- Base UI's input handlers reach the visible `<input>` through `OutlinedInput`'s `inputProps` (v2 ruling), so `NumberInput` in `NumberFieldControl.tsx` is the one place that sees every keystroke before Base UI does.
- Base UI's typed-character allowlist (`getAllowedNonNumericKeys`) already includes the group separator, so programmatically inserted separators are never rejected.

## Design

### `groupWhileTyping` (pure helper)

`src/fields/NumberField/groupWhileTyping.ts`

```ts
export interface Separators { group: string; decimal: string }

/** Locale/format-derived separators, from `Intl.NumberFormat(...).formatToParts(1234567.891)`. */
export function getSeparators(locale?: Intl.LocalesArgument, format?: Intl.NumberFormatOptions): Separators

export interface GroupedText { text: string; caret: number }

/**
 * Re-groups the integer digits of `text` and maps the caret to the same logical
 * position. Fraction digits are left exactly as typed (so `1234.50` stays `1,234.50`
 * and `1234.` keeps its trailing decimal). Returns the input unchanged when the text
 * contains anything other than digits, one leading `-`, the decimal separator, group
 * separators, and whitespace — e.g. a pasted `$` — because Base UI normalizes those on blur.
 */
export function groupWhileTyping(text: string, caret: number, separators: Separators): GroupedText
```

Rules:
- Strip existing group separators, then insert `group` every three integer digits from the right.
- Caret mapping: count "significant" characters (digits, `-`, decimal) strictly before the caret in the input; place the output caret after the same count of significant characters. Group separators are never significant, so backspacing over `1,|000` removes the `1` (the digit before the separator) as users expect from banking inputs.
- Leading zeros are kept as typed (`0001` → `0,001`); Base UI normalizes on blur.
- Empty text → `{ text: '', caret: 0 }`.
- `useGrouping: false` (in `format`) disables grouping: callers must check it before calling; the helper itself is oblivious.

### `NumberFieldControl` wiring

- `NumberFieldControlProps` gains nothing public. `NumberInput` gets `separators: Separators | null` (null = grouping off).
- `NumberFieldControl` computes `const separators = format?.useGrouping === false ? null : getSeparators(locale, format)` (memoized on `locale`/`format`).
- `NumberInput` adds `onChange` to the `inputProps` chain: if `separators`, compute `groupWhileTyping(e.target.value, e.target.selectionStart ?? length, separators)`; when `text` differs from what was typed, set `e.target.value = text` and remember `caret` in a ref; then call `rest.onChange?.(e)` so Base UI parses the grouped text. A `useLayoutEffect` on `inputValue` restores the remembered caret via `setSelectionRange` when the input is focused, then clears the ref.
- Base UI's own blur formatting is untouched.

### `MoneyField`

`src/fields/MoneyField/MoneyField.tsx`

```ts
export type MoneyFieldProps = Omit<NumberFieldProps, 'format' | 'locale'>

/** US dollars on top of NumberField: `$1,234.50` on blur, digits grouped while typing, value in dollars. */
export function MoneyField(props: MoneyFieldProps)
```

- Calls `useEzFormContext('MoneyField')` first so the outside-`<Form>` error names `<MoneyField>` (same pattern as `Select`).
- Renders `<NumberField locale="en-US" format={{ style: 'currency', currency: 'USD' }} step={1} smallStep={0.01} largeStep={10} {...props} />` — consumer `step`/`smallStep`/`largeStep` override the defaults.
- Public exports: `MoneyField`, `MoneyFieldProps`. README: Components table row, rules table rows (`required`, `min`/`max`, `validate`), a short section with a `z.number().min(0)` example.
