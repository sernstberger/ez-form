# ez-form v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an installable React library exposing `Form`, `TextField`, `Select`, `Checkbox`, `Switch`, `SubmitButton` that bind MUI components to react-hook-form with zod validation, with Storybook as docs.

**Architecture:** `<Form>` owns `useForm` (zod resolver) and provides hookform context. Each field calls a shared `useEzField(name)` hook that asserts the context exists and returns `useController` state, then renders the matching MUI component with `error`/`helperText` wired to the zod message. `SubmitButton` reads `isSubmitting` from context.

**Tech Stack:** TypeScript 7 (strict), React 19, MUI 9, react-hook-form 7.87, @hookform/resolvers 5, zod 4, Vite 8 (lib mode) + vite-plugin-dts, Vitest 4 + Testing Library + jsdom, Storybook 10 (`@storybook/react-vite`), pnpm.

**Spec:** `docs/superpowers/specs/2026-09-01-ez-form-v1-design.md`

## Global Constraints

- Package manager is **pnpm**. Never run `npm install` or `yarn` in this repo.
- Peer deps, verbatim: `react`, `react-dom`, `@mui/material`, `@emotion/react`, `@emotion/styled`, `react-hook-form`, `zod`. Runtime dep: `@hookform/resolvers`. Everything else is a devDependency.
- Public exports are exactly: `Form`, `TextField`, `Select`, `Checkbox`, `Switch`, `SubmitButton` and their prop types, plus the `FormMethods` type alias (the type of `onSubmit`'s second argument). No runtime re-exports from react-hook-form.
- Field `name` props are plain `string`.
- Build output: ESM only, `dist/index.js` + `dist/index.d.ts`.
- MUI 9 removed `inputProps`/`inputRef` on Checkbox and Switch; the input ref and a11y attributes go through `slotProps.input`, merged with the consumer's via `mergeSlotProps` from `@mui/material/utils` (the `./utils` subpath is the only exported path for it in MUI 9; never a bare `{ input: { ref } }` literal, which clobbers consumer `slotProps.input`). `TextField` still has `inputRef`.
- **A11y wiring is the error-announcement strategy** (no live region): every field gives RHF the real `<input>` ref so `shouldFocusError` moves focus to the first invalid field on submit; the input carries `aria-invalid` and `aria-describedby` pointing at the helper text. MUI `TextField` does all of this itself. `Checkbox`/`Switch` must do it by hand: `FormHelperText id={helperTextId}`, `'aria-describedby'`/`'aria-invalid'` on `slotProps.input`, and `required` passed to `FormControlLabel` explicitly (it does not read `FormControl` context). MUI 9 `Switch` already sets `role="switch"`; do not set it again.
- **Field prop rule**: omit from the MUI props only what the binding owns (`name`, `value`/`checked`, `error`, the ref prop). Everything the consumer might also want (`onChange`, `onBlur`, `helperText`, `disabled`, `required`, `id`, `slotProps`) is accepted and merged; hookform's handler runs first, the consumer's after. Consumer `disabled` is UI-only and is never passed to `useController({ disabled })` (that strips the value on submit); form-level disabling is `<Form disabled>`.
- **zod 4 idioms** everywhere (tests, stories, README): `z.email({ error })` not `z.string().email()`, `error:` not `message:`, `z.boolean().refine(Boolean, { error })` not `z.literal(true)`, and no `'' as never` / `false as never` in `defaultValues`; omit a key instead (`DefaultValues` is `DeepPartial`; fields render `undefined` as empty).
- `onSubmit` receives `(values, form)`. Spy assertions are `expect(onSubmit).toHaveBeenCalledWith(values, expect.anything())`.
- Stories: hoist the submit spy to module scope (`const onSubmit = fn()`) and reference it from decorators/args; never `onSubmit={fn()}` inline.
- **One folder per component**: `src/<Name>/` (or `src/fields/<Name>/`) holds `<Name>.tsx`, `<Name>.test.tsx`, `<Name>.stories.tsx`, and an `index.ts` that is exactly `export * from './<Name>'`. Shared hooks (`useEzFormContext`, `useEzField`, `useBooleanField`) stay flat. Import components by folder (`./fields/TextField`), never by file.
- Import MUI components by path (`@mui/material/TextField`), never from the barrel `@mui/material`. It keeps the lib tree-shakeable for consumers.
- Every task ends with `pnpm typecheck && pnpm test` green before committing.
- **Testing conventions (Kent C. Dodds / Testing Library):**
  - Query by what the user sees, in this priority: `getByRole` (with `name`) > `getByLabelText` > `getByText`. Never `getByTestId`, never `container.querySelector`.
  - Always use `screen`; never destructure queries from `render`.
  - Interactions go through `const user = userEvent.setup()` at the top of the test, then `await user.click(...)` / `await user.type(...)`. Never `fireEvent`, never call `userEvent.*` statically.
  - Async: `await screen.findBy*` for elements that appear later. `waitFor` only for non-query assertions, one assertion per `waitFor`, no side effects inside it.
  - No manual `act()`. No `cleanup()`. Assert with jest-dom matchers (`toBeDisabled`, `toBeChecked`, `toBeInTheDocument`), not raw DOM properties.
  - Assert calls with `toHaveBeenCalledWith` / `toHaveBeenCalledTimes`; never reach into `mock.calls`.
  - Vitest runs with `restoreMocks: true`, so a `vi.spyOn(console, 'error')` is restored after the test automatically. Never call `vi.restoreAllMocks()` by hand.
  - Helper-text wiring is asserted with `toHaveAccessibleDescription(...)` (follows `aria-describedby`), never by querying ids.
  - Hooks are tested with `renderHook` (+ `wrapper` for providers), not ad-hoc probe components.
  - Test behavior, not implementation: no assertions on internal state, no mocking of react-hook-form or MUI.
  - Flat `describe`/`it`; a small explicit setup function is fine, `beforeEach` mutations are not.

`src/useEzFormContext.ts`:

```ts
import { useFormContext, type FieldValues, type UseFormReturn } from 'react-hook-form'

export function useEzFormContext<T extends FieldValues = FieldValues>(
  componentName: string,
): UseFormReturn<T> {
  const ctx = useFormContext<T>()
  if (!ctx) {
    throw new Error(`ez-form: <${componentName}> must be rendered inside <Form>`)
  }
  return ctx
}
```

- [ ] **Step 4: Implement Form**

`src/Form/Form.tsx`:

```tsx
import type { FormHTMLAttributes, ReactNode } from 'react'
import { FormProvider, useForm, type DefaultValues, type FieldValues, type Mode } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import type { z } from 'zod'

export interface FormProps<S extends z.ZodType<FieldValues, FieldValues>>
  extends Omit<FormHTMLAttributes<HTMLFormElement>, 'onSubmit'> {
  schema: S
  onSubmit: (values: z.output<S>) => void | Promise<void>
  defaultValues?: DefaultValues<z.input<S>>
  mode?: Mode
  children: ReactNode
}

export function Form<S extends z.ZodType<FieldValues, FieldValues>>({
  schema,
  onSubmit,
  defaultValues,
  mode = 'onSubmit',
  children,
  ...formProps
}: FormProps<S>) {
  const methods = useForm<z.input<S>, unknown, z.output<S>>({
    resolver: zodResolver(schema),
    defaultValues,
    mode,
  })

  return (
    <FormProvider {...methods}>
      <form noValidate {...formProps} onSubmit={methods.handleSubmit((values) => onSubmit(values))}>
        {children}
      </form>
    </FormProvider>
  )
}
```

`src/Form/index.ts`:

```ts
export * from './Form'
```

The arrow around `onSubmit` is deliberate: hookform calls its handler with `(values, event)`, and the public `onSubmit` type promises `values` only.

If `zodResolver(schema)` does not typecheck against the three `useForm` generics, cast at the call site: `resolver: zodResolver(schema) as Resolver<z.input<S>, unknown, z.output<S>>` (import `Resolver` from react-hook-form). Do not loosen the `FormProps` generics.

`src/fields/TextField/TextField.tsx`:

```tsx
import MuiTextField, { type TextFieldProps as MuiTextFieldProps } from '@mui/material/TextField'
import { useEzField } from '../useEzField'

export type TextFieldProps = Omit<
  MuiTextFieldProps,
  'name' | 'value' | 'onChange' | 'onBlur' | 'error' | 'inputRef'
> & {
  name: string
}

export function TextField({ name, helperText, disabled, ...rest }: TextFieldProps) {
  const { field, fieldState } = useEzField(name, 'TextField')
  const { ref, value, disabled: fieldDisabled, ...fieldProps } = field

  return (
    <MuiTextField
      {...fieldProps}
      value={value ?? ''}
      disabled={disabled ?? fieldDisabled}
      inputRef={ref}
      error={fieldState.invalid}
      helperText={fieldState.error?.message ?? helperText}
      {...rest}
    />
  )
}
```

Why `value ?? ''`: an `undefined` value makes MUI switch from controlled to uncontrolled and warn. Why `disabled` is destructured from both props and `field`: neither object may carry a `disabled` key into a spread, so the merge `disabled ?? fieldDisabled` (consumer wins, hookform's form-level disabled otherwise) is the only place it is set.

`src/SubmitButton/SubmitButton.tsx`:

```tsx
import Button, { type ButtonProps } from '@mui/material/Button'
import { useFormState } from 'react-hook-form'
import { useEzFormContext } from '../useEzFormContext'

export type SubmitButtonProps = Omit<ButtonProps, 'type'>

export function SubmitButton({
  disabled,
  variant = 'contained',
  children = 'Submit',
  ...rest
}: SubmitButtonProps) {
  useEzFormContext('SubmitButton') // guard only; useFormState reads control from context
  const { isSubmitting } = useFormState()

  return (
    <Button type="submit" variant={variant} disabled={disabled} loading={isSubmitting} {...rest}>
      {children}
    </Button>
  )
}
```

MUI 9's `loading` renders `disabled={disabled || loading}` plus a `CircularProgress` (`role="progressbar"`) labelled by the button, so async feedback comes for free and the consumer's `disabled` stays a separate prop.

- [ ] **Step 3: Implement useBooleanField**

`src/fields/useBooleanField.ts`:

```ts
import { useId, type ChangeEvent } from 'react'
import { useEzField } from './useEzField'

export function useBooleanField(name: string, componentName: string) {
  const { field, fieldState } = useEzField(name, componentName)
  const helperTextId = useId()
  const errorMessage = fieldState.error?.message
  return {
    name: field.name,
    checked: Boolean(field.value),
    onChange: (e: ChangeEvent<HTMLInputElement>) => field.onChange(e.target.checked),
    onBlur: field.onBlur,
    inputRef: field.ref,
    disabled: field.disabled,
    invalid: fieldState.invalid,
    errorMessage,
    helperTextId,
  }
}
```

`helperTextId` (React `useId`, SSR-stable) is what links the `FormHelperText` to the input via `aria-describedby`; MUI's `FormHelperText` has no default id and `SwitchBase` never sets `aria-invalid`, so without this the zod message under a checkbox is invisible to assistive tech.

`src/fields/Checkbox/Checkbox.tsx`:

```tsx
import type { ReactNode } from 'react'
import MuiCheckbox, { type CheckboxProps as MuiCheckboxProps } from '@mui/material/Checkbox'
import FormControl from '@mui/material/FormControl'
import FormControlLabel from '@mui/material/FormControlLabel'
import FormHelperText from '@mui/material/FormHelperText'
import { mergeSlotProps } from '@mui/material/utils'
import { useBooleanField } from '../useBooleanField'

export type CheckboxProps = Omit<MuiCheckboxProps, 'name' | 'checked'> & {
  name: string
  label: ReactNode
  helperText?: ReactNode
}

export function Checkbox({
  name,
  label,
  helperText,
  disabled,
  required,
  onChange,
  onBlur,
  slotProps,
  ...rest
}: CheckboxProps) {
  const f = useBooleanField(name, 'Checkbox')
  const text = f.errorMessage ?? helperText

  return (
    <FormControl error={f.invalid} disabled={disabled ?? f.disabled} required={required}>
      <FormControlLabel
        label={label}
        required={required}
        control={
          <MuiCheckbox
            {...rest}
            name={f.name}
            checked={f.checked}
            onChange={(e, checked) => {
              f.onChange(e)
              onChange?.(e, checked)
            }}
            onBlur={(e) => {
              f.onBlur()
              onBlur?.(e)
            }}
            slotProps={{
              ...slotProps,
              input: mergeSlotProps(slotProps?.input, {
                ref: f.inputRef,
                'aria-invalid': f.invalid || undefined,
                'aria-describedby': text ? f.helperTextId : undefined,
              }),
            }}
          />
        }
      />
      {text ? <FormHelperText id={f.helperTextId}>{text}</FormHelperText> : null}
    </FormControl>
  )
}
```

Why each piece:

- `FormControlLabel` wraps the control in a `<label>`, so the accessible name comes from nesting; only the helper text needs an explicit association (`FormHelperText id` + `aria-describedby`).
- `required` must be passed to `FormControlLabel` explicitly: it reads its own prop or `control.props.required`, not the `FormControl` context. The asterisk is `aria-hidden`; the native `required` attribute is inert under `noValidate`.
- `mergeSlotProps` handles the object-or-function `slotProps.input` shape and is what MUI's own `Switch` uses; consumer keys win, so overriding `ref` is the consumer's explicit choice.
- `field.ref` on the real `<input>` is what lets RHF's `shouldFocusError` move focus to the first invalid checkbox on submit; with `aria-describedby` in place the screen reader then reads the zod message.
- If `SlotProps<'input', ...>` rejects `ref`, fall back to `mergeSlotProps(slotProps?.input, { ref: f.inputRef, ... } as Record<string, unknown>)` with a one-line comment citing the MUI 9 `inputRef` removal.

```tsx
import type { ReactNode } from 'react'
import MuiSwitch, { type SwitchProps as MuiSwitchProps } from '@mui/material/Switch'
import FormControl from '@mui/material/FormControl'
import FormControlLabel from '@mui/material/FormControlLabel'
import FormHelperText from '@mui/material/FormHelperText'
import { mergeSlotProps } from '@mui/material/utils'
import { useBooleanField } from '../useBooleanField'

export type SwitchProps = Omit<MuiSwitchProps, 'name' | 'checked'> & {
  name: string
  label: ReactNode
  helperText?: ReactNode
}

export function Switch({
  name,
  label,
  helperText,
  disabled,
  required,
  onChange,
  onBlur,
  slotProps,
  ...rest
}: SwitchProps) {
  const f = useBooleanField(name, 'Switch')
  const text = f.errorMessage ?? helperText

  return (
    <FormControl error={f.invalid} disabled={disabled ?? f.disabled} required={required}>
      <FormControlLabel
        label={label}
        required={required}
        control={
          <MuiSwitch
            {...rest}
            name={f.name}
            checked={f.checked}
            onChange={(e, checked) => {
              f.onChange(e)
              onChange?.(e, checked)
            }}
            onBlur={(e) => {
              f.onBlur()
              onBlur?.(e)
            }}
            slotProps={{
              ...slotProps,
              input: mergeSlotProps(slotProps?.input, {
                ref: f.inputRef,
                'aria-invalid': f.invalid || undefined,
                'aria-describedby': text ? f.helperTextId : undefined,
              }),
            }}
          />
        }
      />
      {text ? <FormHelperText id={f.helperTextId}>{text}</FormHelperText> : null}
    </FormControl>
  )
}
```

~~~~markdown
## Install

pnpm add ez-form @mui/material @emotion/react @emotion/styled react-hook-form zod

## Components

| Component | Wraps | Extra props |
|---|---|---|
| `Form` | `useForm` + `<form>` | `schema`, `onSubmit(values, form)`, `defaultValues?`, `mode?`, `disabled?` |
| `TextField` | MUI `TextField` | `name` |
| `Select` | MUI `TextField select` | `name`, `options: readonly { value, label }[]` |
| `Checkbox` | MUI `Checkbox` | `name`, `label`, `helperText?`, `required?` |
| `Switch` | MUI `Switch` | `name`, `label`, `helperText?`, `required?` |
| `SubmitButton` | MUI `Button` | `loading` while submitting |

Every field shows its zod message as helper text (linked to the input with `aria-describedby`; the first invalid field is focused on submit). Fields must be rendered inside `<Form>`. Consumer `onChange`/`onBlur` handlers run after the form's own.

Need `reset`, `setError`, `watch`? `onSubmit` receives the form methods as its second argument (the same object `useFormContext()` returns), so the component that owns the form can handle server errors or reset after success:

```tsx
<Form
  schema={schema}
  defaultValues={emptyValues}
  onSubmit={async (values, form) => {
    const res = await save(values)
    if (res.error) form.setError('email', { message: res.error })
    else form.reset()
  }}
>
```

Inside child components use `useFormContext()` from `react-hook-form`.

Numbers: `TextField` hands zod the string from the input, so use `z.coerce.number()` (not `z.number()`) for numeric text fields.
~~~~
