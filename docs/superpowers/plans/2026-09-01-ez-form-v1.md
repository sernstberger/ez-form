# ez-form v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an installable React library exposing `Form`, `TextField`, `Select`, `Checkbox`, `Switch`, `SubmitButton` that bind MUI components to react-hook-form with zod validation, with Storybook as docs.

**Architecture:** `<Form>` owns `useForm` (zod resolver) and provides hookform context. Each field calls a shared `useEzField(name)` hook that asserts the context exists and returns `useController` state, then renders the matching MUI component with `error`/`helperText` wired to the zod message. `SubmitButton` reads `isSubmitting` from context.

**Tech Stack:** TypeScript 7 (strict), React 19, MUI 9, react-hook-form 7.87, @hookform/resolvers 5, zod 4, Vite 8 (lib mode) + vite-plugin-dts, Vitest 4 + Testing Library + jsdom, Storybook 10 (`@storybook/react-vite`), pnpm.

**Spec:** `docs/superpowers/specs/2026-09-01-ez-form-v1-design.md`

## Global Constraints

- Package manager is **pnpm**. Never run `npm install` or `yarn` in this repo.
- Peer deps, verbatim: `react`, `react-dom`, `@mui/material`, `@emotion/react`, `@emotion/styled`, `react-hook-form`, `zod`. Runtime dep: `@hookform/resolvers`. Everything else is a devDependency.
- Public exports are exactly: `Form`, `TextField`, `Select`, `Checkbox`, `Switch`, `SubmitButton` and their prop types. No re-exports from react-hook-form.
- Field `name` props are plain `string`.
- Build output: ESM only, `dist/index.js` + `dist/index.d.ts`.
- MUI 9 removed `inputProps`/`inputRef` on Checkbox and Switch; use `slotProps={{ input: { ref } }}`. `TextField` still has `inputRef`.
- Import MUI components by path (`@mui/material/TextField`), never from the barrel `@mui/material`. It keeps the lib tree-shakeable for consumers.
- Every task ends with `pnpm typecheck && pnpm test` green before committing.

- [ ] **Step 3: Implement useEzFormContext**

`src/useEzFormContext.ts`:

```ts
import { useFormContext, type FieldValues, type UseFormReturn } from 'react-hook-form'

export function useEzFormContext<T extends FieldValues = FieldValues>(
  componentName: string,
): UseFormReturn<T> {
  const ctx = useFormContext<T>()
  if (!ctx) {
    throw new Error(`ez-form: <${componentName}> must be rendered inside <Form>`)
  }
  return ctx
}
```

- [ ] **Step 4: Implement Form**

`src/Form.tsx`:

```tsx
import type { FormHTMLAttributes, ReactNode } from 'react'
import { FormProvider, useForm, type DefaultValues, type FieldValues, type Mode } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import type { z } from 'zod'

export interface FormProps<S extends z.ZodType<FieldValues, FieldValues>>
  extends Omit<FormHTMLAttributes<HTMLFormElement>, 'onSubmit'> {
  schema: S
  onSubmit: (values: z.output<S>) => void | Promise<void>
  defaultValues?: DefaultValues<z.input<S>>
  mode?: Mode
  children: ReactNode
}

export function Form<S extends z.ZodType<FieldValues, FieldValues>>({
  schema,
  onSubmit,
  defaultValues,
  mode = 'onSubmit',
  children,
  ...formProps
}: FormProps<S>) {
  const methods = useForm<z.input<S>, unknown, z.output<S>>({
    resolver: zodResolver(schema),
    defaultValues,
    mode,
  })

  return (
    <FormProvider {...methods}>
      <form noValidate {...formProps} onSubmit={methods.handleSubmit(onSubmit)}>
        {children}
      </form>
    </FormProvider>
  )
}
```

If `zodResolver(schema)` does not typecheck against the three `useForm` generics, cast at the call site: `resolver: zodResolver(schema) as Resolver<z.input<S>, unknown, z.output<S>>` (import `Resolver` from react-hook-form). Do not loosen the `FormProps` generics.

- [ ] **Step 4: Implement TextField**

`src/fields/TextField.tsx`:

```tsx
import MuiTextField, { type TextFieldProps as MuiTextFieldProps } from '@mui/material/TextField'
import { useEzField } from './useEzField'

export type TextFieldProps = Omit<
  MuiTextFieldProps,
  'name' | 'value' | 'onChange' | 'onBlur' | 'error' | 'inputRef'
> & {
  name: string
}

export function TextField({ name, helperText, ...rest }: TextFieldProps) {
  const { field, fieldState } = useEzField(name, 'TextField')
  const { ref, value, disabled, ...fieldProps } = field

  return (
    <MuiTextField
      {...fieldProps}
      value={value ?? ''}
      disabled={rest.disabled ?? disabled}
      inputRef={ref}
      error={fieldState.invalid}
      helperText={fieldState.error?.message ?? helperText}
      {...rest}
    />
  )
}
```

Why `value ?? ''`: an `undefined` value makes MUI switch from controlled to uncontrolled and warn. Why `disabled` is computed before the `rest` spread: `field.disabled` is `undefined` by default and would otherwise clobber a consumer's `disabled`.

```ts
import type { ChangeEvent } from 'react'
import { useEzField } from './useEzField'

export function useBooleanField(name: string, componentName: string) {
  const { field, fieldState } = useEzField(name, componentName)
  return {
    name: field.name,
    checked: Boolean(field.value),
    onChange: (e: ChangeEvent<HTMLInputElement>) => field.onChange(e.target.checked),
    onBlur: field.onBlur,
    inputRef: field.ref,
    disabled: field.disabled,
    errorMessage: fieldState.error?.message,
  }
}
```

```tsx
    <Form {...args}>
      <SignupFields submitLabel="Save (1.5s)" />
    </Form>
  ),
```

~~~~markdown
# ez-form

MUI + react-hook-form + zod, wired together so you write plain JSX.

```tsx
import { z } from 'zod'
import { Form, TextField, Select, Checkbox, Switch, SubmitButton } from 'ez-form'

const schema = z.object({
  email: z.string().email('Invalid email'),
  role: z.enum(['admin', 'user']),
  tos: z.literal(true, { message: 'Required' }),
  newsletter: z.boolean(),
})

export function Signup() {
  return (
    <Form schema={schema} defaultValues={{ email: '', role: 'user', tos: false, newsletter: false }} onSubmit={(v) => console.log(v)}>
      <TextField name="email" label="Email" />
      <Select name="role" label="Role" options={[{ value: 'admin', label: 'Admin' }, { value: 'user', label: 'User' }]} />
      <Checkbox name="tos" label="I accept the terms" />
      <Switch name="newsletter" label="Newsletter" />
      <SubmitButton />
    </Form>
  )
}

## Components

| Component | Wraps | Extra props |
|---|---|---|
| `Form` | `useForm` + `<form>` | `schema`, `onSubmit(values)`, `defaultValues?`, `mode?` |
| `TextField` | MUI `TextField` | `name` |
| `Select` | MUI `TextField select` | `name`, `options: { value, label }[]` |
| `Checkbox` | MUI `Checkbox` | `name`, `label`, `helperText?` |
| `Switch` | MUI `Switch` | `name`, `label`, `helperText?` |
| `SubmitButton` | MUI `Button` | disabled while submitting |

Every field shows its zod message as helper text. Fields must be rendered inside `<Form>`.
Need `watch`, `reset`, or `setError`? Use `useFormContext()` from `react-hook-form` inside the form.
~~~~
